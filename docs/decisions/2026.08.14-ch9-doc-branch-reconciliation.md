# 9장(리서치 프레임 밖 갭 분석) 문서를 어느 브랜치에 어떻게 얹을지

**상황:** `docs/planning/2026.07.13-ai-engineering-application-plan.md`에 9장을 추가하는 작업을 진행하던 중, 원래 8장이 있던 `docs/ai-native-readiness` 브랜치를 병렬로 다른 세션이 이미 사용해 `main`으로 merge까지 마친 상태였다. 그 사이 내가 작업하던 브랜치(`chore/ai-native-harness-improvements`)는 `main`에서 분기해 8장이 없는 옛날 버전을 들고 있었고, `git stash pop`으로 합치려다 `.beads/issues.jsonl`과 문서 파일 모두 실제 3-way 충돌이 났다.

**옵션:**
- (A) 옛 8장 사본을 그대로 유지한 채 9장을 얹는다 — 두 곳에서 같은 챕터를 따로 관리하게 됨.
- (B) 옛 8장 사본을 버리고, `main`에 이미 병합된 최신 8장 위에 9장만 얹는다.
- (C) 지금 합치지 말고 `docs/ai-native-readiness`가 `main`에 완전히 반영될 때까지 기다린다.

**결정:** (B) — 중복 제거, 9장만 남김. 최신 `main`의 8장(오탈자/집계 수정이 이미 반영된 버전)을 그대로 가져오고, 그 위에 9장만 새로 얹었다. 브랜치 이름은 이미 merge되어 비어있던 `docs/ai-native-readiness`를 그대로 재사용했다.

**이유:** 8장은 다른 세션이 이미 관리하는 "정본"이 있는데, 내 브랜치에 오래된 사본을 별도로 유지하면 다음에 누가 봐도 어느 쪽이 최신인지 헷갈리고, 향후 8장이 또 수정될 때마다 두 곳을 동기화해야 하는 부담이 생긴다. 실제로 이 판단을 하기 전, 옛 사본에 남아있던 오류(총점 집계 O27/△8/X3 vs 수정된 O26/△6/X3)를 그대로 얹을 뻔했다 — 최신 버전을 정본으로 취급하는 게 맞다는 걸 재확인한 사례이기도 하다.
