# Context Packets

`docs/planning/2026.07.13-ai-engineering-application-plan.md` §4.6에서 설계했던 내용을 독립 문서로 분리했다 (§8.5 갭 5번). 각 스킬의 "JIT Search Strategy"/읽기 순서 절이 이 문서의 해당 패킷을 가리킨다.

패킷은 코드 탐색 자체를 대체하지 않는다 — `codegraph_explore`로 실제 심볼을 찾는 것과 별개로, "이 작업 유형에서 놓치기 쉬운 것"을 미리 알려주는 체크리스트에 가깝다.

## Backend API Change Packet

- 먼저 볼 파일: `src/api-spec/openapi.yaml`, `src/db/schema.ts`, 해당 도메인 `src/domain/<domain>/`
- 금지 사항:
  - OpenAPI 갱신 없이 라우터/구현부터 먼저 고치지 않는다
  - `drizzle-kit push`나 그 밖의 방식으로 로컬 D1에 스키마를 수동 적용하지 않는다 (`yarn mig:local`만 사용)
- 검증 명령: `yarn gen:api`, `yarn test:backend`, `yarn tsc --noEmit`
- 참고 스킬: `dowin-backend-api-spec`, `dowin-backend`

## Frontend API Integration Packet

- 먼저 볼 파일: `src/api/generated/`의 관련 훅, 해당 도메인 `_hooks/`, 실제로 그 훅을 쓰는 기존 컴포넌트
- 금지 사항:
  - 페이지 컴포넌트 내부에 복잡한 상태/폼 로직을 그대로 섞어 넣지 않는다 (훅/도메인 레이어로 분리)
  - 캐시 무효화·롤백 전략이 이미 있는 도메인에서 새 패턴을 임의로 만들지 않는다
- 검증 명령: `yarn test:frontend`, `yarn tsc --noEmit`
- 참고 스킬: `dowin-frontend-api-connect`

## Billing Entitlement Packet

- 먼저 볼 파일: 결제/구독 도메인 로직(`src/domain/billing/`), 관련 스키마, 권한 체크 서비스
- 금지 사항:
  - 권한 우회가 가능한 느슨한 체크(예: 클라이언트 값만 신뢰)를 넣지 않는다
  - `dowin-backend-security-check` 승인 전에는 결제/권한 변경을 배포하지 않는다
- 검증 명령: 관련 vitest 스위트, `dowin-backend-security-check`
- 참고 스킬: `dowin-backend`, `dowin-backend-security-check`

## WebView Bridge Packet

- 먼저 볼 파일: `src/lib/bridge.ts`, `src/types/bridge.ts`, `docs/dev/app-webview/`
- 금지 사항:
  - 모바일 앱(webview) fallback 동작을 검증하지 않고 bridge 호출을 추가/변경하지 않는다
  - 네이티브 전용 API를 브라우저 환경 분기 없이 직접 호출하지 않는다
- 검증 명령: `yarn test:frontend`, 관련 브릿지 유닛 테스트
- 참고 스킬: `dowin-frontend-webview`

## Product Update Packet

- 먼저 볼 파일: `src/content/product-updates.ts`, `src/lib/product-updates.ts`, 업데이트 노트 페이지/대시보드 카드 컴포넌트
- 금지 사항:
  - 14일 NEW 노출 규칙을 벗어난 날짜를 임의로 넣지 않는다
- 검증 명령: `yarn test:frontend`
- 참고 스킬: `dowin-product-updates`

## Harness/Security Packet

- 먼저 볼 파일: `AGENTS.md`, `codex.md`, `.agents/skills/*`, `.claude/settings.json`, MCP 도구가 걸려 있으면 `docs/dev/common/2026.08.13-mcp-tool-policy.md`
- 금지 사항:
  - 안전 가드레일(Safety Guardrails) 문구를 완화하는 방향으로 수정하지 않는다
  - `.claude/settings.json`의 `permissions.deny` 항목을 사용자 명시 승인 없이 제거하지 않는다
- 검증 명령: 없음 (리뷰 중심) — `dowin-harness-security-check` 체크리스트로 대체
- 참고 스킬: `dowin-harness-security-check`
